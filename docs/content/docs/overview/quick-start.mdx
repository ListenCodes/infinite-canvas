# Quick Start

To try the project, deploy or start the `web/` frontend in backward-compatible local mode. Deploy the complete Hatchet cloud runtime when you need accounts, durable server-side tasks, and cross-device assets.

## Deploy with Vercel

Import the repository into Vercel. The root `vercel.json` builds `web/`. This is a local-mode deployment: AI requests are sent directly from the browser to the user's OpenAI-compatible endpoint, so no application server is required.

## Run locally

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas/web
bun install
bun run dev
```

Open `http://localhost:3000`.

## Run with Docker

```bash
docker build -t infinite-canvas .
docker run --rm -p 3000:3000 infinite-canvas
```

## First-time setup

- Open Settings and enter your `Base URL`, `API Key`, and model names.
- Open `/prompts` to fetch prompt repositories directly from the browser and cache them in IndexedDB.
- Configure WebDAV if you want to synchronize canvases, assets, and generation history across devices.

When only `web/` is running, canvas projects, My Assets, and user API keys remain in the browser. Complete local, Hatchet Cloud, and Hatchet OSS service stacks are under `infra/compose`; read `docs/operations/deployment.md` before enabling cloud mode. Platform provider keys and Hatchet tokens belong only in API/Worker server environments.
