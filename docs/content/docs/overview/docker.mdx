# Docker Deployment

## Start local mode

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The root Compose file builds the Vite frontend and serves it with non-root Nginx. In this local mode, canvases, My Assets, generation history, and user API keys stay in the browser, while prompt repositories are fetched directly by the frontend.

## Complete cloud mode

Use `infra/compose/local` for the repeatable Hatchet Lite development stack, `infra/compose/cloud` for Hatchet Cloud with managed Supabase, or `infra/compose/oss` for the pinned Hatchet OSS control plane. Cloud mode requires immutable digests for the separate `infinite-canvas-web`, `infinite-canvas-api`, and `infinite-canvas-worker` images, plus Auth, the business database, private object storage, and Hatchet configuration.

The business PostgreSQL database owns projects, tasks, permissions, and credit facts; private object storage owns assets; Hatchet owns execution facts. Platform credentials stay in API/Worker server environments. Follow `docs/operations/` for migration, backup, rollback, and v1/v2 Worker drain procedures, and never deploy an example `replace-me` digest.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
